## Running the navigation regressions

With the test dependencies, Playwright, and its Chromium browser installed, run:

```sh
QUANTIFY_BROWSER_TESTS=1 python -m pytest tests/test_browser_navigation.py -q
```

In PowerShell, set `$env:QUANTIFY_BROWSER_TESTS = '1'`, then run `python -m pytest tests/test_browser_navigation.py -q`; remove the variable afterward if later suite runs should skip browser checks. Without the variable, the browser class is skipped. It uses a temporary SQLite database, a local HTTP server, and controlled failure responses. The checks cover failed-location retry, an inert previous screen while navigation is pending, Order's date after visiting a past day, location/trading-date boundaries, incomplete historical expectations, and the distinction between rebuilt baskets and recorded receipts. They do not claim coverage of every route or screen.

## Limits and deployment notes

- New infrastructure and core tests use isolated databases and synthetic data. Square request interception proves the credential boundary without contacting Square. No real Stripe transaction, email delivery, model call, or supplier order was tested in this follow-up.
- Server-configured Square connections now need `QUANTIFY_SQUARE_INTERNAL_LOCATION`; credentials saved through Settings still take priority. See [Live setup](LIVE_SETUP.md#square) and the [API reference](API_REFERENCE.md).
- Historical menu names, current prices, saved recipes, and staffing assumptions are not fully versioned. Bounding sales-derived analysis does not recreate historical versions of those settings.
- Historical reconciliation leaves saved rows unchanged, including when neighboring dates are first scored. For schema compatibility, numeric aggregate columns in day_accuracy still contain internal placeholders for newly incomplete records. Direct SQL consumers must use the nullable item/coverage data or the reconciled public API; those placeholders are not complete forecasts. Old reconstructed item revenue was not stored, so changed membership can also leave expected revenue unknown.
- Register totals matching daily sales can detect some incomplete ticket feeds, but cannot certify that every provider record has arrived. Daily sales, ticket counts, hourly measurements, and historical forecast coverage remain separately qualified.
- The current profile route edits the display name, not the account email. The deliberate local email-code preview when mail is unconfigured remains part of the existing local setup contract.
- This work does not establish provider availability, live model quality, legal wage completeness, or pricing profitability. The [pricing decision](PRICING_DECISION.md) remains a launch hypothesis; [personalization](PERSONALIZATION.md) records geography and cost-source limits.
